# Plan: Agent Architecture 专家团队协作设计

## Context

项目已完成：核心体验原则 (P1-P8)、世界设定书 (10个文件)、游戏设计文档 v1。
现状：Agent 架构停留在分散的概念描述（GM、NPC Agent、级联传播等），没有统一的、可实施的架构设计。
目标：通过专家团队协作讨论，产出一个**真实可行的 agent architecture**，覆盖"单场景完整"范围（1场景 + 2-3 NPC + GM + 信息传播 + 骰子检定）。

**不输出代码，不写具体 prompt。** 输出的是经过多轮专家讨论和审计的**宏观架构设计**。Prompt 相关内容只定义作用、输入、输出，不涉及具体 prompt 文本。

---

## 一、专家团队构成

| 角色 | 代号 | 专长 | 职责 |
|------|------|------|------|
| **系统架构师** | `SA` | 分布式系统、数据流、接口设计 | 定义 agent 间通信协议、状态管理、数据模型、系统边界 |
| **LLM 工程师** | `LE` | Context 管理、Multi-agent 编排、LLM 约束 | 解决 LLM 特有约束（token 限制、幻觉、一致性），定义每个 prompt 的作用/输入/输出（不写具体 prompt） |
| **游戏设计师** | `GD` | 游戏机制、玩家体验、叙事设计 | 确保架构服务于 P1-P8 体验原则和世界设定书规则 |
| **对抗审计师** | `AA` | 安全、边界测试、故障分析 | 每轮结束后审计：找漏洞、边界情况、玩家 exploit、系统故障点 |

### 运作规则
- 每轮由 SA 或 LE 主导提案，GD 从体验角度验证，AA 最后审计
- 专家之间可以反驳、质疑、提出替代方案
- 每轮输出：**讨论过程**（含分歧点）+ **结论**（含未解决问题）
- Human 在每轮结束后审阅，可以修正方向、否决结论、追加约束

---

## 二、讨论议程（6 轮）

### Round 1: Agent 身份与职责边界
**主导**: SA
- 系统中到底有哪些 agent？各自的精确职责？
- GM 的 Core GM / Story Tracker 拆分如何落地？
- Audit Module 的独立性如何实现？
- 单场景范围内的最小 agent 集合？

### Round 2: 通信协议与数据流
**主导**: SA + LE
- Agent 间消息格式和路由规则？
- 双层信息过滤在数据流中如何体现？
- "隔墙有耳"和级联传播的收敛/终止机制？

### Round 3: 状态管理与记忆架构
**主导**: LE
- 每个 agent 的状态 schema？
- Context window 预算与管理策略？
- 信息域（谁知道什么）的运行时管理？

### Round 4: 游戏主循环与编排
**主导**: SA + GD
- 完整回合的执行流程？
- 编排器设计（中心化 vs 事件驱动）？
- 弹性回合和错误恢复？

### Round 5: 信息机制集成
**主导**: GD + LE
- D20 + Insight 在 agent 交互中的触发点？
- 信息传播失真、凡神反比、信念侵蚀的更新时机？
- 双层过滤（Agent 自主 + GM 约束）的宏观实现策略？

### Round 6: 对抗审计与压力测试
**主导**: AA
- 玩家 exploit、LLM 幻觉、context overflow 风险？
- 单点故障分析？
- 前 5 轮结论中的内部矛盾？

## 三、每轮输出格式

```
## Round N: [主题]

### 讨论过程
- SA: [观点/提案]
- LE: [回应/补充/反驳]
- GD: [体验验证/设计约束]
- AA: [审计意见]

### 结论
[达成共识的设计决策]

### 未解决问题
[需要后续轮次或 Human 决定的问题]

### AA 审计摘要
[本轮风险点和边界情况]
```

---

## 四、执行方式

每轮启动 4 个子 agent（SA / LE / GD / AA），给予各自的专家角色定义、当前轮核心问题、前序轮结论、游戏设计文档和世界设定书作为参考。

流程：SA/LE 产出提案 → GD 验证 → AA 审计 → 汇总为讨论报告 → Human 审阅 → 确认/修正/否决 → 下一轮

---

## 五、最终交付物

6 轮讨论后产出 **Agent Architecture Design Document**（`.claude/plans/agent-architecture.md`）：
1. Agent 角色定义与职责矩阵
2. 通信协议规范（消息格式、路由规则）
3. 状态模型（每个 agent 的 state schema）
4. 游戏主循环流程图
5. 信息机制集成规范
6. Prompt 清单（每个 prompt 的作用/输入/输出，不含具体文本）
7. 风险清单与缓解策略
