# Plan: 《Jump Jump》游戏设计文档 v1

## Context

基于《悟空传》构建一个「反英雄」视角的 LLM 驱动文字博弈游戏。核心理念：悟空是极少数，凡人才是世界的主角。玩家在西游世界中扮演不同的凡人/小人物，在有限行动内通过对话、谈判、抉择来求生存、争利益。场景间通过暗线（因果链）相连，经验可"复利"。最终是一个「凡人在西游世界中的贡献模拟器」。

---

## 一、核心体验原则（Core Experience Pillars）

以下原则定义玩家应获得的核心体验。所有设计决策（场景、机制、Agent行为）必须服务于这些原则。如果某个设计与原则冲突，原则优先。

### P1 — 被忽视者的主场（The Overlooked Take Center Stage）

**定义**: 玩家扮演的不是「没有法力的凡人」，而是西游叙事中**被忽视的普通角色** — 可能有点小本事，但在宏大叙事中只是路人甲。游戏的核心视角翻转是：这些被忽视的群体才是世界的真正主体。

**设计指引**:
- 玩家角色绝不会成为「关键先生」或「天选之人」
- 玩家能感知到宏大事件（如大闹天宫）正在发生，但只能从边缘介入
- 身份本身就是约束 — 你的地位决定了你能接触到什么、能做什么

### P2 — 多元生存博弈（Survival in Many Forms）

**定义**: 每个场景围绕不同维度的「生存」展开博弈。「生存」不局限于肉体存活，而是涵盖多种形态：生命的生存、职场的生存、理想的存活、道义下不得已的责任的生存。每个场景有不同的生存侧重，避免体验单一化。

**设计指引**:
- 每个场景在立项时必须明确其「生存维度」，且不与其他场景重复
- 博弈的对手不一定是「敌人」— 可以是盟友、恩人、甚至自己的良心
- 场景难度来自于「两难」而非「强敌」

### P3 — 道德重量（Moral Weight）

**定义**: 关键抉择必须让玩家**在屏幕前真正纠结**。选择设计不是「好 vs 坏」，而是「好 vs 好」或「坏 vs 更坏」。每个选项都有合理的理由，不存在道德高地。

**设计指引**:
- 禁止设计有「明显正确答案」的抉择
- 每个选项必须有至少一个令人心痛的代价
- NPC 不分「好人」「坏人」— 每个人都有自己的苦衷和合理性
- 事后回顾时，玩家应该能理解「如果我是另一个角色，我可能也会这样做」
- **蜜罐选项（Honeypot Choices）**: 偶尔出现看似轻松的「捷径」或「逃避」选项。蜜罐背后是更大的代价 — 在后续场景中更难、或事后发现失去了什么。「逃避」只是角色层面的逃避，事件不会因此停下。唯有主动面对、主动争取、主动博弈才能真正改变处境。
- **慰藉设计（Comfort Design）**: 虽然选择沉重，但游戏需要给予玩家情感上的慰藉时刻 — 一句温暖的话、一个意外的善意、一次小小的胜利。防止全程高压导致玩家情绪崩溃。

### P4 — 理想与枷锁（Freedom vs. Chains）

**定义**: 每个角色都有自己想追求的「自由」和「理想」，但现实（身份、责任、宿命、权力结构）构成枷锁。抉择发生在理性与感性之间 — 没有纯理性人物，也没有纯感性人物。每个人都在博弈，也都是棋盘上的棋子。

**设计指引**:
- 每个玩家角色和 NPC 在设计时必须定义其「理想」和「枷锁」
- 游戏中最好的时刻应该是：玩家为了某个理想放弃了更「理性」的选择，或者为了生存放弃了理想
- 西游世界的宿命感要贯穿始终 — 你可以反抗，但代价真实

### P5 — 暗线隐晦，心性闭合（Hidden Threads, Inner Closure）

**定义**: 场景间的因果暗线是隐晦的，未必有边界，也不保证完全闭环。即使发现了真相，更多时候只是「释然」「原来如此」。这种闭合发生在**人物心性层面** — 对角色而言的释怀和成长 — 而不是故事的终结。因为西游世界的一切终究服从于某种更大的规划和目的。

**设计指引**:
- 暗线的「回报」不是机制奖励（如加属性），而是叙事层面的「恍然大悟」
- 允许玩家在不发现暗线的情况下完成场景 — 暗线是锦上添花，不是必要条件
- 有些暗线可以永远不揭开 — 这本身就是设计意图

### P6 — 涟漪而非巨浪（Ripples, Not Tidal Waves）

**定义**: 玩家的行为可以改变西游历史的**程度**，但不能改变**主线走向**。核心叙事（取经、大闹天宫、五指山）是既定的。你能做到的最好结果，可能只是让被压在五指山下的孙悟空多了一棵桃树。但这棵桃树是真实的，它证明了你存在过。

**设计指引**:
- 主线事件不可阻止，但细节/程度可以被影响
- 「影响力报告」应展示：你改变了什么微小的事，而不是「你拯救了世界」
- 玩家的成就感来自「我在历史的缝隙中留下了痕迹」

### P7 — 发现感（The Joy of Discovery）

**定义**: 探索被奖励，好奇心有回报。玩家应体验到「我发现了别人没注意到的东西」的快感 — 一句 NPC 的闲话暗藏线索、一个不起眼的角落有关键信息、一次看似无用的对话在三个场景后变成救命稻草。

**设计指引**:
- 每个场景必须有至少 2-3 个可被发现但不强制的隐藏信息
- 发现的回报形式多样：洞察值、暗线推进、额外行动次数、NPC 态度变化
- 信息分层 — 表面信息人人可得，深层信息需要主动探索

### P8 — 无力感与微光（Despair and Glimmers）

**定义**: 作为被忽视的小人物，「无力感」是叙事的必然组成部分。但如果全程无力，玩家会放弃。设计原则是：**在绝望中总有一丝可以抓住的微光**。这道微光可能很小、很难抓住、抓住了也不能改变大局，但它是真实的希望。

**设计指引**:
- 每个场景的最低谷处必须设计至少一个「微光时刻」— 一个可以争取的小小转机
- 微光不保证成功 — 但保证存在
- 情绪节奏遵循「紧张 → 喘息 → 发现 → 抉择 → 余波」的曲线，避免全程高压

## 二、游戏基础设定

### 游戏定义
- **类型**: LLM 驱动的回合制文字博弈游戏
- **核心循环**: 阅读情境 → 选择行动/对话 → Agent 系统级联反应 → GM 评估 → 叙事推进
- **技术路线**: CLI 优先（可用 agent 自动评估） → Web 前端（配图、排版、氛围）
- **接口设计**: CLI 和 Web 共享同一套核心引擎接口，UI 层为薄壳

### 叙事结构
- **倒叙开场 + 时间顺序展开**（3-5 个场景原型）
- **Scene 0（序章）**: 「尘埃落定」— 一切结束后的回忆视角，暴露隐藏信息，为后续埋伏笔
- **Scene 1-4**: 按悟空传时间线展开，每个场景一个不同凡人视角
- 具体场景基于《悟空传》原文设计（待研读后确定）

### 角色设计
- 每个场景扮演完全不同的人，角色间不知道彼此存在
- 命运/因果暗线相连（类似《云图》）
- 玩家作为"超视角"可利用前序场景获得的信息

### 结局
- 无标准结局，重在体验
- 最终输出「影响力报告」— 你的决策在西游世界中产生了什么涟漪

## 二、Agent 系统架构（核心）

### 设计哲学
**Agent 也是玩家** — NPC 不是响应器，而是 LLM 驱动的独立玩家，和 human 在同一个博弈场中。这是一个多 Agent 信息不对称博弈系统。

### Agent 角色

| 角色 | 职责 |
|------|------|
| **Player** | Human 玩家，通过 `@角色名` 对话或直接行动 |
| **NPC Agent** | 独立人格，有自己的动机/底线/秘密/信息域，自主决策 |
| **GM System** | 世界规则执行者：全局评估、传播调控、蝴蝶效应判定、叙事推进 |

### 回合循环

```
Player Action（两种类型）
  ├─ @NPC 对话 → 直接影响目标 NPC → 级联传播（有泄露风险）
  └─ 直接行为 → GM 判定影响范围 → 受影响 NPC 各自反应
    ↓
[NPC 级联传播]（最大 K 轮上限，GM 可提前终止）
  - Agent 自由意志传播（基于各自利益判断）
  - 传播有「隔墙有耳」风险 + 信息损耗/失真
  - GM 全程监控，判断何时收敛
    ↓
[GM 全局评估]
  - 汇总状态变化
  - 判定蝴蝶效应（小行动 → 不成比例的后果）
  - 更新世界状态
  - 调节回合弹性
    ↓
[叙事摘要] → 返回 Player
```

### 双层信息过滤

信息在 Agent 间传递时经过两层控制：
- **Layer 1 — Agent 自主**: 基于动机/利益决定「想说什么」（可能隐瞒、欺骗、选择性透露）
- **Layer 2 — GM 约束**: 基于世界观判定「能说什么」（凡人不可能知道天庭机密等）

### 「隔墙有耳」机制

信息传播存在暴露风险，采用**骰子检定系统**（参考博德之门 D20）：
- 场景有基础风险值（市集高、密室低）
- GM 根据对话敏感度、周围角色等动态调整
- 检定结果分档：完全安全 / 部分暴露 / 完全暴露
- **洞察值可作为防御**：高洞察值可保护关键信息不被截获

### NPC 人格建模（待深入）

每个 NPC Agent 需结构化定义：
- **身份**: 谁，什么地位，在场景中的角色
- **动机**: 想要什么，为什么
- **底线**: 绝对不会做什么
- **秘密**: 知道什么别人不知道的
- **行为模式**: 面对威胁/利诱/谈判时的倾向
- **关系网**: 和其他 NPC 的关系、利益冲突点

### 记忆系统（待深入）

核心挑战：
- 每个 Agent 维护独立的信息域（知道什么/不知道什么）
- Agent 背后的博弈结果写入各自 memory
- Context 管理：如何在有限 token 内保持关键信息
- 跨场景记忆传递（暗线系统）

### GM 评估框架（待深入）

GM 需要评估的维度：
- 玩家行动的价值/影响力
- 蝴蝶效应判定（何时触发、触发多大的连锁反应）
- 回合弹性调节（智慧博弈可延长行动次数）
- 暗线触发判定
- 整体叙事节奏控制

## 三、玩法机制

### 回合制但弹性
- 每场景有基础行动次数
- 非硬编码 — 可通过智慧博弈延长/缩短
- 触发条件：隐藏对话、关键谈判成功、获取特殊资源、戳到关键人物的点

### 洞察值系统
- **用途**: 判断信息可信度 + 保护信息不被截获
- **距离衰减**: 信息源离人物越近 → 洞察越准，但信息量越低
- **Agent 也有洞察值** — 它们也在评估彼此的信息真伪
- **获取方式**:
  - 场景结束统一结算
  - 发现暗线可额外获取
  - 推测「真正发生的事」（每回合 N 次尝试机会）
- **回顾**: 场景结束后展示「幕后」— NPC 们背后实际发生了什么

### 场景间暗线（因果链）
- Scene A 伏笔 → Scene B 揭示 → Scene C 利用
- 每个场景的决策影响后续场景的初始条件
- 序章（倒叙）提前暴露的信息在后续场景中可被利用

## 四、技术架构

### 模块布局
```
jump-jump/
├── src/
│   ├── core/              # 核心引擎
│   │   ├── game.py            # 游戏主循环
│   │   ├── scene.py           # 场景管理
│   │   ├── turn.py            # 回合系统（弹性回合计数）
│   │   └── history.py         # 跨场景历史/暗线追踪
│   ├── agents/            # Agent 系统
│   │   ├── base.py            # Agent 基类（统一接口）
│   │   ├── gm.py              # GM System
│   │   ├── npc.py             # NPC Agent
│   │   ├── propagation.py     # 级联传播引擎
│   │   └── memory.py          # Agent 记忆管理
│   ├── mechanics/         # 游戏机制
│   │   ├── dice.py            # 骰子检定系统
│   │   ├── insight.py         # 洞察值系统
│   │   └── thread.py          # 暗线/因果链系统
│   ├── scenes/            # 场景定义
│   │   └── ...
│   ├── models/            # 数据模型
│   │   ├── state.py           # 游戏状态
│   │   ├── action.py          # 玩家行动
│   │   └── info.py            # 信息域模型（谁知道什么）
│   ├── ui/                # 界面层（薄壳）
│   │   └── cli.py             # CLI 界面
│   └── config/
│       └── settings.py
├── scenarios/             # 场景剧本（YAML/JSON）
├── books/                 # 原著资料（已有）
└── code_plan/             # 设计文档
```

### 关键接口（CLI/Web 共享）
- `GameEngine.start_scene(scene_id)` — 加载场景
- `GameEngine.player_action(action)` — 处理玩家行动（对话或行为）
- `GameEngine.get_narrative()` — 获取当前叙事
- `GameEngine.get_state()` — 获取可见状态（受洞察值限制）

## 五、下一步行动

1. **解压研读《悟空传》** — 确定关键剧情节点，设计 3-5 个具体场景
2. **深入设计待定模块** — NPC 人格建模、记忆系统、GM 评估框架
3. **设计场景剧本** — 世界观、角色、暗线、骰子检定参数
4. **搭建核心引擎** — game loop + turn system + agent 级联传播
5. **实现 CLI 原型** — 先跑通一个场景的完整体验
6. **扩展到多场景** — 验证暗线复利和跨场景因果

## 六、验证方式
- CLI 单场景：对话博弈、回合弹性、隔墙有耳、洞察值均可体验
- 多场景：Scene A 决策确实影响 Scene B 初始条件
- 暗线：序章暴露的信息在后续场景中可被利用
- Agent 系统：NPC 有独立判断，信息不对称可感知
